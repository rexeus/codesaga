The knowledge section now reports territories: the repository cut into non-overlapping slices, so that every file belongs to exactly one territory. Detail 1 is the packages (found by their manifests, such as `package.json`, `Cargo.toml` or `go.mod`) or the top-level folders, each finer detail goes one folder step deeper, and a territory that holds most of the files is split further so that no single territory stands for the repository. A territory is a `package`, a `folder`, or the small leftovers of a folder grouped as `other` files. `knowledge.territories` carries every detail (`details`, each with `detail`, `totalTerritories` and `territories`) with the truck factor, islands and orphaned flags of each territory, the `recommendedDetail` for the team size and why (`reason`), and `totalTerritories` per detail before `--limit`. `analyze` takes `--detail <n>` (config key `detail`, MCP parameter `detail`) to start at another detail; `depth` still works as a deprecated alias in all three. Its terminal view shows the riskiest territories of that detail instead of directories. `knowledge.directories` stays but is deprecated. `thresholds.territories` states the new constants.

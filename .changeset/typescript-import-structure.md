`deepDives.typescript.imports` describes how the code depends on itself. Every literal module request (`import`, `export ... from`, `import("x")`, `require("x")`) is resolved without a file system access: relative paths with `.js` read as their `.ts` sources, `index` files, the `paths` and `baseUrl` of the governing `tsconfig`, and the repository's own workspace packages through `exports` (conditions `types`, `import` and `default`), `types`, `module`, `main` and `src`. A specifier that points into the repository and finds no file is counted as unresolved, with its share and the five most frequent; packages outside the repository are counted as external and not resolved. `files` gives the import cycles (the count, the largest, and the three largest with up to ten files each; by value edges, with the figures that count type-only edges beside them, and `typeOnly` for cycles that exist only through `import type`), the median and top five fan-in and the top five fan-out, with test files left out of every figure. `territories` is the dependency map between the territories at the report's default detail: edges with file counts, `ca`, `ce` and the instability `ce / (ca + ce)` (Robert C. Martin's metric, a description and not a verdict), the edges toward a territory at least 0.3 more unstable between territories with at least 5 edges each (`thresholds.typescript.imports`), and the cycles between territories. Every territory's `typescript` gains `imports`, `importedBy` and `inCycle`. `--limit` cuts the lists of the map. All of it is additive within `schemaVersion` 1.
